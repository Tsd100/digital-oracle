# DO 自动趋势系统设计

## 1. 背景与目标

当前 DO 历史页面能够归档和展示分析报告，但历史报告主要依赖自然语言解析。不同报告的表达、分析周期和概率口径不稳定，导致页面出现较多“待确认”或“暂不可比”，也难以直接回答观点如何变化。

本轮改造面向启用新版本后的报告，建立统一、确定性的趋势数据链路。每次通过 Codex、命令行或 Web 完成 DO 分析后，系统自动：

1. 保存完整报告；
2. 写入结构化趋势快照；
3. 按分析对象和周期与上一次有效结论比较；
4. 生成变化事件和中文摘要；
5. 更新趋势可视化页面。

本轮不批量清洗旧报告。旧报告继续保留和浏览，新的连续趋势统计从第一份符合新格式的报告开始。

## 2. 已确认的产品决策

- 覆盖所有 DO 分析入口：Codex Skill、CLI、Web。
- 每次分析完成后自动更新时间线，并返回本次变化摘要。
- 短线、波段、中期三条轨道独立比较。
- 使用完全规则化的结构数据，不调用模型二次判定历史结论。
- 采用统一发布管道，不以目录扫描作为主要入库方式。
- 仅要求未来报告遵循新数据契约，不重做全部历史报告。

## 3. 总体架构

所有分析入口在报告完成后调用同一个发布接口：

```text
DO 分析（Codex / CLI / Web）
        ↓
可读报告 + 标准趋势数据
        ↓
统一发布管道 publish_report
        ├─ 保存完整报告
        ├─ 写入趋势快照
        ├─ 计算变化事件
        ├─ 更新当前趋势状态
        └─ 返回中文变化摘要
```

目录扫描保留为兼容旧资料和人工恢复的工具，但不承担新报告的正常发布职责。

### 3.1 模块边界

建议把能力拆为以下独立模块：

- **趋势数据契约**：定义字段、枚举、版本和校验规则。
- **发布服务**：负责幂等检查、事务写入和统一返回结果。
- **趋势引擎**：只接收结构化快照，生成确定性的变化事件。
- **摘要生成器**：根据变化事件使用固定模板生成中文摘要。
- **查询服务**：为时间线页面提供当前状态、曲线、事件和报告详情。
- **入口适配器**：Codex、CLI、Web 分别负责收集输入并调用同一个发布服务。

趋势引擎不读取报告正文。页面也不在每次访问时重新解析报告。

## 4. 报告数据契约

每份新报告包含正常的 Markdown 正文和一个机器可读数据块。数据块使用带版本号的 JSON，示例：

```json
{
  "schema_version": "1.0",
  "analysis_id": "do-20260921-gold-001",
  "analysis_at": "2026-09-21T14:30:00+08:00",
  "data_as_of": "2026-09-21T14:00:00+08:00",
  "subjects": [
    {
      "subject_id": "gold",
      "subject_name": "黄金",
      "instrument": "XAUUSD",
      "quote_currency": "USD",
      "quote_unit": "oz",
      "horizons": {
        "short": {
          "direction": "bearish",
          "confidence": 72,
          "summary": "短线仍有回调压力"
        },
        "swing": {
          "direction": "bullish",
          "confidence": 65,
          "summary": "波段上升结构尚未破坏"
        },
        "medium": {
          "direction": "strong_bullish",
          "confidence": 78,
          "summary": "中期仍受降息和央行购金支撑"
        }
      }
    }
  ]
}
```

### 4.1 固定周期

| 标识 | 中文名称 | 默认范围 |
|---|---|---|
| `short` | 短线 | 1～5 个交易日 |
| `swing` | 波段 | 1～4 周 |
| `medium` | 中期 | 1～3 个月 |

报告可以缺少某个周期，但不能使用其他名称替代这三个标识。缺少周期表示“本次未分析”，不表示“观点未变”。

### 4.2 方向枚举

| 枚举 | 中文 | 分值 |
|---|---|---:|
| `strong_bullish` | 明确看多 | +2 |
| `bullish` | 偏多 | +1 |
| `neutral` | 中性/震荡 | 0 |
| `bearish` | 偏空 | -1 |
| `strong_bearish` | 明确看空 | -2 |
| `insufficient` | 信息不足 | 不入曲线 |

`confidence` 必须是 0～100 的整数。信息不足的数据不覆盖上一条有效状态。

### 4.3 概率和关键位置

可选概率项必须带稳定的 `scenario_id`、概率值和统计期限。只有 `subject_id`、周期、`scenario_id` 和统计期限都一致时才可比较。

关键位置按类型分别保存：`support`、`resistance`、`target`、`invalidation`。比较前必须确认分析对象、合约或标的、计价币种和单位一致。伦敦金、沪金和黄金 ETF 不混合成同一条数值曲线。

## 5. 统一发布流程

发布服务的逻辑顺序如下：

1. 解析并校验趋势数据块；
2. 根据分析对象、数据截止时间、报告内容摘要和来源生成发布指纹；
3. 查询是否已经成功发布；
4. 在一个数据库事务中保存发布记录、趋势快照、变化事件和当前状态；
5. 提交事务后生成页面可用的查询结果；
6. 返回发布状态和中文变化摘要。

同一指纹再次发布时直接返回已有结果，不产生重复节点。同一天内容或数据截止时间不同的多次分析分别保留。

### 5.1 失败处理

- 报告正文可以保存，但无效趋势数据不得进入有效趋势轨道。
- 校验错误必须指出具体字段，例如 `黄金.short.direction 缺失`。
- 数据库写入失败时回滚本次趋势事务，不留下半条记录。
- 发布可以安全重试。
- 页面显示最近成功发布时间、更新轨道数和未解决错误数。
- 页面展示缺失的具体原因，不再统一显示“待确认”。

## 6. 趋势判定规则

趋势引擎只比较“同一分析对象、同一标的口径、同一周期”的相邻两次有效快照。

### 6.1 方向事件

| 事件 | 规则 |
|---|---|
| `initiated` | 之前没有有效快照 |
| `continued` | 方向和强度分值相同 |
| `strengthened` | 同一多空侧，绝对分值增大 |
| `weakened` | 同一多空侧，绝对分值减小 |
| `shifted` | 中性与多空状态之间变化 |
| `reversed` | 正分值与负分值之间切换 |
| `insufficient` | 本次数据不足，不更新有效状态 |

例如 `中性 → 偏多 → 明确看多 → 偏多 → 偏空` 应依次得到 `shifted → strengthened → weakened → reversed`。

### 6.2 置信度

方向不变时，置信度变化用于补充强弱说明：

- 小于 5 个百分点：基本不变；
- 5～14 个百分点：增强或减弱；
- 不少于 15 个百分点：显著增强或显著减弱。

置信度不能单独制造方向反转。

### 6.3 连续状态

每条轨道维护：

- 当前方向；
- 同侧连续次数；
- 当前观点开始时间；
- 持续时长；
- 最近反转时间；
- 最近有效报告；
- 最近置信度。

本次缺少某周期时，页面可继续显示上一次有效状态，但必须标明“本次未分析”，且连续次数不增加。

### 6.4 周期分化

三个周期分开计算。当短线和中期方向相反时，系统生成固定模板提示，例如“短线偏空，波段及中期偏多，当前存在周期分化”。该提示是结构说明，不构成新的行情预测。

## 7. 数据模型

在现有报告数据基础上增加以下逻辑实体，具体表名可在实施计划中按现有数据库命名规范确定：

### 7.1 发布记录

保存分析编号、发布指纹、来源、分析时间、数据截止时间、报告位置、内容摘要、数据版本、规则版本、发布状态和错误详情。

### 7.2 趋势快照

每个对象和周期一条记录，保存方向、置信度、摘要、概率、关键位置、口径信息及原始结构化数据。

### 7.3 变化事件

保存前后快照、事件类型、方向分值变化、置信度变化、概率变化、关键位置变化和生成摘要所需字段。

### 7.4 当前趋势状态

保存每个对象和周期的最新有效状态、连续次数、开始时间、最近反转时间和最新报告引用，用于快速加载页面首屏。

原始报告和原始结构化数据不可被派生结果覆盖。规则版本升级后，可以从快照重建变化事件。

## 8. 可视化设计

### 8.1 首屏

页面顶部显示短线、波段、中期三张当前状态卡片。每张卡片包含方向、置信度、相对上次变化、连续次数、持续时间、核心理由和数据截止时间。

用户打开首屏即可回答：当前三个周期怎么看、与上次相比发生了什么、观点持续多久、最近一次反转何时发生。

### 8.2 三周期曲线

纵轴固定为 -2 至 +2 的方向分值，横轴为分析时间。三条曲线可单独开关。节点展示分析时间、变化类型、置信度、核心理由、数据截止时间和完整报告入口。

节点形状区分延续、增强、减弱、反转、本次未分析和发布异常。文字标签始终保留，颜色只作为辅助信息。

### 8.3 辅助区域

- 最近变化流优先展示有实质变化的事件；
- 概率区只展示同一 `scenario_id` 的连续数据；
- 关键位置区分别展示支撑、压力、目标和失效位；
- 自动化状态显示最近发布结果、更新时间、更新轨道数、重复数和错误数；
- 点击任何节点可打开对应完整报告并查看当时结论及与前次的差异。

## 9. 三个入口的接入方式

### 9.1 Codex Skill

DO Skill 把生成标准数据和调用发布服务列为报告交付的必做收尾步骤。只有发布结果返回后，本次分析才算完成。完成提示包含趋势变化摘要。

### 9.2 CLI

命令行分析完成后直接调用同一 Python 发布接口，并以适合终端阅读的格式输出发布状态和变化摘要。另保留显式发布命令用于重试和恢复。

### 9.3 Web

Web 后台在报告生成后调用同一发布接口，不重复实现趋势逻辑。前端读取发布结果展示摘要，并从统一查询接口加载趋势页面。

## 10. 测试与验收

### 10.1 单元和集成验证

- 数据契约接受有效数据并拒绝非法枚举、范围和单位；
- 方向变化路径能正确产生各类事件；
- 三个周期、不同对象和不同计价口径不会交叉比较；
- 概率仅在相同情景和期限下比较；
- 缺少周期不会伪造延续事件；
- 同一报告重复发布不会重复入库；
- 事务失败不会留下部分趋势数据；
- 规则版本可以用于重建派生事件。

### 10.2 真实入口验收

分别通过 Codex Skill、CLI 和 Web 发布一份新报告，确认：

1. 报告成功保存；
2. 趋势快照自动入库；
3. 变化摘要立即返回；
4. 页面出现对应节点；
5. 重复发布不产生重复记录；
6. 错误数据能显示字段级原因。

### 10.3 页面验收

使用一组连续样例覆盖方向转向、增强、减弱、反转、置信度变化、关键位置变化、周期分化和缺少周期。页面首屏必须清楚显示当前状态、最近变化、持续时间、最近反转、来源报告和自动化状态。

## 11. 分阶段实施

1. **数据基础**：完成数据契约、发布服务、幂等和事务写入，接入三个入口并返回摘要。
2. **趋势引擎**：完成方向事件、置信度、连续状态、概率、关键位置和周期分化规则。
3. **可视化页面**：实现状态卡片、三周期曲线、变化流、概率和关键位置、运行状态及报告联动。
4. **全链路验收**：用三个真实入口验证自动发布、重复发布、错误恢复和页面更新。

每个阶段完成相关测试和实际流程验证后再进入下一阶段。

## 12. 本轮边界

本轮包含未来报告的统一自动发布、规则化趋势数据、三周期趋势、变化摘要和可视化升级。

以下能力留作后续独立设计：

- 批量清洗全部旧报告；
- 到期后自动判断预测是否正确；
- 按周期统计历史准确率；
- 观点反转后的行情归因；
- 跨资产关联分析；
- 自动生成周度趋势复盘。
