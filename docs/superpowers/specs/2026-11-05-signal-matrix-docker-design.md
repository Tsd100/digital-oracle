# DO 状态矩阵看板与 NAS Docker 设计

## 目标

将主题卡片墙改为适合跨主题比较的研判状态矩阵，同时为 fnOS NAS 的 Docker Compose 部署建立可持久化、可健康检查、可回滚的单容器运行边界。

## 看板结构

1. 顶部只保留主题数量、报告数量、最近更新时间和近期变化数。
2. 当前三周期矩阵按主题分行、短期/波段/中期分列；没有结构化数据时显示空白，不把旧报告方向伪装成当前周期判断。
3. 历史研判矩阵按主题分行、分析日期分列；每次分析是独立色块，空白表示没有分析，不把旧判断延伸到下一次报告。
4. 点击色块打开右侧详情抽屉，展示方向、时间、证据、原文摘录和完整时间线入口。
5. 最近变化按时间倒序展示旧方向到新方向，作为辅助视图。

## 数据契约

管理汇总接口为每个主题增加 `history` 数组，字段为 `analysis_at`、`direction`、`evidence`、`hash` 和 `title`。接口仍返回 `horizons`，前端按 `short/swing/medium` 排序。历史矩阵最多默认显示最近 18 个不同分析日期，可横向滚动查看。

## Docker 边界

- 应用使用 Gunicorn 单进程多线程运行，避免当前内存 SSE 注册表跨进程丢失。
- `DO_TIMELINE_DB`、`DO_CHAT_DB`、`DO_REPORTS_DIR`、`DO_ARCHIVE_DIR` 指向容器持久化目录。
- `/healthz` 同时检查两套 SQLite 数据库。
- Compose 使用非 root 用户、`restart: unless-stopped`、健康检查和独立数据/报告挂载。
- 静态页面不得依赖公共 CDN。
- 数据库和报告不进入镜像；部署前备份，升级时保留旧镜像标签。

## 验收

- 桌面和手机无横向页面溢出，矩阵自身可横向滚动。
- 矩阵色块数量与 API 有效历史节点一致。
- 点击色块能加载对应报告详情。
- `/ask` 在无网络时仍能渲染常用 Markdown。
- Python 全套测试、管理页和时间线浏览器测试通过。
- Docker 配置可解析；若本机 Docker 引擎不可用，明确标为未完成真实构建。
