# DO 历史分析时间线开发计划

> 执行方式：按阶段逐项开发和验收；每项完成后核对原报告与索引结果。执行前保留工作区现有未提交改动，不覆盖其他开发内容。

**目标：** 把 DO 历史报告和今后的新报告汇成可追溯的主题时间线，回答“同一主题的判断在何时、因何发生变化”。

**架构：** 原始 Markdown 与 Web 问答记录是事实来源；独立 SQLite 索引保存统一元数据和结构化结论，不修改原文。确定性规则负责去重、时间排序、可比性检查和数值差分；复盘 agent 只根据索引及原文证据解释变化，无法确认的字段标记待核对。

**技术栈：** Python 标准库、SQLite、现有 Flask Web 端；第一阶段无需新增第三方依赖。

---

## 一、已核对的现状与边界

- `reports/` 有本地 Markdown 报告；`D:\坚果云同步\WS\Digital-Oracle-Reports\` 当前有 70 份 Markdown 归档。`web/db.py` 的 `history` 表另存 Web 问题和完整报告；这些入口尚未统一索引。
- `SKILL.md` 已规定数据总结、矛盾与共振、情景概率、结论和监控阈值，但旧报告的标题、表头、标的和时间写法不完全一致。
- 当前工作区有未提交及未跟踪文件。实施时只新增本计划明确的文件，并对已有文件做最小修改；不得批量重命名、移动或改写历史报告。
- 历史报告里的价格、概率和阈值仅代表报告当时的判断。复盘输出必须标明分析时间、原始数据时间、预测窗口及盘中/收盘口径，不把旧判断说成当前行情。

## 二、数据契约

每份原报告对应一个 `report` 记录；一份报告可对应多个 `subject`（例如黄金、白银、有色板块），每个主题可有多个不同预测窗口的 `view`。索引至少存：

| 层级 | 必备字段 | 规则 |
|---|---|---|
| 来源 | `source_kind`、`source_path_or_id`、`sha256` | 文件用规范化绝对路径及内容哈希；Web 历史用问答 ID。相同内容的归档副本归到同一逻辑报告，同时保留所有来源路径。 |
| 时间 | `analysis_at`、`data_as_of`、`market_session`、`horizon_start/end` | 均使用带时区时间；不明确的时间为空并标记待核对。文件修改时间只能用于发现，不能冒充分析时间。 |
| 主题 | `subject_id`、`subject_label`、`instrument_id`、`scope` | 主题、标的、板块范围分别存；`黄金`、`白银`、`有色板块`可以建立关联，不能自动视为同一预测。 |
| 判断 | `stance`、`summary`、`confidence`、`scenarios`、`thresholds`、`evidence_spans` | 保留报告原文、数值及单位；情景保留原标签，不强行映射不同报告的情景。每项结论附来源位置。 |
| 质量 | `extraction_status`、`review_note`、`parser_version` | `confirmed`、`needs_review`、`unparsed`；旧报告提取结果可人工校正且保留校正记录。 |

比较结果按“同主题 + 同范围 + 可比预测窗口”生成。价格比较还要求相同标的、合约、单位及行情口径；不满足时显示“不可直接比较”及原因。概率仅在情景语义一致或有人工确认的映射时计算差值。结论变化分为 `上调`、`下调`、`维持`、`口径变化`、`无法判断`，并与概率变化分别展示。

## 四、开发顺序与阶段性交付

1. **最小可用版：阶段 0—2。** 可对已有报告提问“近三次有色判断怎么变了”，得到带证据的中文对比；先通过命令行和专用 agent 使用。
2. **日常使用版：阶段 3。** 以后每份 DO 报告自动登记，Web 页面可直接浏览时间线。
3. **长期复盘版：阶段 4。** 到期后核对实际走势，逐步积累可评价的预测记录。

每阶段先写有区分力的测试，再实现最小功能；测试重点放在去重、时间口径、同主题但不同标的、情景不可比、人工校正和原报告可追溯。每阶段结束运行对应的定向测试和一次真实归档只读导入核对。不得仅凭测试通过宣称历史提取全部准确。

## 五、交付判定

- 用户能选择一个主题，看到按分析时间排列的所有可识别报告，并打开每份原文。
- 用户能一眼分辨：判断方向变没变、概率变没变、证据与阈值变没变、数据口径是否相同。
- 旧报告、归档目录和 Web 历史都能纳入；重复副本只出现一次，来源仍可追溯。
- 未知、不完整或不可比的信息有明确标记，可人工校正；系统不会把盘中与收盘、黄金与白银、不同合约或不同预测期限直接做数值对比。
- 第一版不依赖实时市场抓取即可完成历史结论比较；若要声称阈值已经触发，必须另行取得并标注对应时点的真实行情。

## 六、实施记录（2026-09-17）

阶段 0—3 已有可运行版本：三类来源导入、去重、保留原文与来源、人工校正、逐次比较、`do-history` 技能和 Web `/timeline` 页面均已实现。首次真实导入为 89 个来源、80 份不同内容，75 份至少一个关键字段待核对；这反映历史格式差异，不能称为 80 份完整结构化报告。旧报告的未知正文时间单列，并显示文件名时间线索但不参与逐次比较。

阶段 4 目前仅实现“提供已核实的窗口内观察值时验证单个阈值”的基础函数。自动行情回放、情景结果判定和概率校准统计尚未实现，不能展示预测准确率。上线使用的主功能是历史结论变化对比；事后验证须继续补齐真实市场序列和合约口径。
